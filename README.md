# 8th Pay Commission Pension Calculator — static site

Plain HTML + CSS + vanilla JS. Nothing to build at deploy time, no external libraries or fonts, no backend. Pages are pre-generated by `tools/build.py`.
Status of data: **30 October 2026** (DR 63% from 1 July 2026, Cabinet 28.10.2026) (`lastUpdated` in `assets/app.js`).

## 1. Deploy on Vercel

**Option A — drag and drop (fastest)**
1. Unzip `8cpc-pension-site.zip`.
2. Go to vercel.com → *Add New… → Project* → choose *Deploy without Git* / drag the `8cpc-pension-site` folder in.
3. Framework preset: **Other**. Build command: *none*. Output directory: leave empty (root). Deploy.

**Option B — GitHub import (recommended for updates)**
1. Create a new GitHub repo and push the contents of this folder (so `index.html` and `vercel.json` sit at the repo root).
2. Vercel → *Add New… → Project* → Import the repo → Framework **Other**, no build command, output directory = root → Deploy.
3. Every later `git push` redeploys automatically.

**Or with the CLI:** `npm i -g vercel` then run `vercel --prod` inside the folder.

Then add your domain: Vercel project → *Settings → Domains*.

## 2. Replace the domain placeholder (`https://YOURDOMAIN.com`)

The domain is **one variable**: `DOMAIN` at the top of `tools/build.py`. Everything else is generated from it — canonical tags, hreflang, Open Graph/Twitter image URLs, JSON-LD, `sitemap.xml`, `robots.txt` and the contact address (`CONTACT_EMAIL` defaults to `contact@<your domain>`; override it on the next line if you use a different inbox).

1. Set `DOMAIN = "https://your-real-domain.in"` (no trailing slash) in `tools/build.py`.
2. Run `python3 tools/build.py` from the site root.
3. Run the checks (section 6) and redeploy.

After going live: submit `https://your-domain/sitemap.xml` in Google Search Console.

## 3. Updating rates when official figures arrive

**Single source of truth: the `CONFIG` object at the top of `assets/app.js`.** The pages read it directly (no network request, so the strict CSP is untouched). `assets/rates.json` is only a public, machine-readable copy generated from CONFIG by `node tools/export-rates.js` (run automatically by `build.py`); `tools/test.js` fails if the two ever differ.

*Why not load rates.json at runtime?* It would mean an extra request, a flash of fallback values before the fetch completes, and two copies of every rate to keep in step. A single inline CONFIG is simpler and cannot fail, so the JSON is published for transparency only.

| When this happens | Change in CONFIG |
|---|---|
| **New DR announced** (e.g. July 2026 instalment) | Append `{ from: "2026-07", pct: 63, ref: "DoPPW OM … dt …" }` to `drHistory`; set `currentDR: 63`; set `drNextAssumed: null` (the DA/DR calculator then shows the arrears of that official hike, labelled "Official"); update `drNote`. When the next instalment becomes due, set `drNextFrom: "2027-01"` and, only if you want an estimate pre-filled, `drNextAssumed`. |
| Official fitment factor announced | `officialFitmentFactor: 2.xx` and `officialNoticeUrl: "https://pib.gov.in/..."`. It becomes the default everywhere (main, pre-2016), is labelled OFFICIAL, starred in tables, a banner appears, and the chart gets a column. |
| 8th CPC gives a new minimum / maximum pension | `newMinPension`, `newMaxPension`, `newMaxFamilyNormal`, `newMaxFamilyEnhanced`. `null` = estimate as 7th CPC limit × factor. |
| DR on revised pension doesn't start at 0 | `newDRPercent`. |
| Date of effect fixed / payment month known | `effectiveFrom`, `defaultPaymentMonth`. |
| Age slabs / FMA change | `additionalPension`, `fixedMedicalAllowance`. |
| Any change | bump `lastUpdated: "YYYY-MM-DD"` (shown on every page). |

Then:
1. Update the text that is **not** driven by CONFIG: `UI[...]["status_text"]` in `tools/build.py` and the same key in `I18N` in `app.js` (status strip), the DR table/FAQs on `/da-dr-calculator/`, `/latest-update/`, and any "not announced" sentences. Add a dated entry at the top of `CHANGELOG` in `tools/build.py` naming the order. Bump `LAST_UPDATED` / `LAST_UPDATED_HUMAN`.
2. `python3 tools/build.py` → regenerates every page, the sitemap and `assets/rates.json`.
3. Run the checks (section 6). The fixed-value assertions for the original cases in `tools/test.js` assume DR 63% (currentDR) and a ₹9,000 minimum — adjust them if you change those. The DR, finder and pre-2016 tests pass explicit rates, so they keep working.
4. Redeploy (push to GitHub or drag the folder again).

## 3a. Adding a page

1. In `tools/build.py` add a `PAGES.append(dict(...))` block: `path` (with trailing slash), `crumb`, a **unique** `title` (≤ 65 chars) and `desc`, one `h1`, `lead`, `body` (HTML, `<h2>` and below), `faqs` (list of (question, answer) — every page carries FAQPage + BreadcrumbList JSON-LD), and `related=rel(...)`. Add the path to `REL_ALL` so other pages can link to it.
2. For a calculator page: set `webapp=True` and either `calc=True` (main calculator) or `widget=<html>` (a custom tool; give its section `id="calc"` for the skip link). Put the logic in `app.js` as pure functions (export them for `tools/test.js`), add a `setupXxx()` in the UI section, and put every label in `I18N` in **both** `en` and `hi` (`test.js` checks parity; `build.py` reads labels from `app.js` through Node, so you never type them twice).
3. Optionally add it to `NAV` (keep the top nav short — pensioners use phones) or `FOOTER_TOOLS`.
4. Build, run all checks, add a `CHANGELOG` entry. The sitemap updates itself.

## 5. How the calculation works

The full, user-facing version is the `/how-we-calculate/` page. In short:

```
additional = ceil(basic × age%)            age%: 80→20, 85→30, 90→40, 95→50, 100→100
DR         = ceil((basic + additional) × DR%)          (on the full pension, before commutation)
newBasic   = ceil(basic × factor), floored at newMin (9000×factor) and capped at newMax (limit×factor)
newTotal   = newBasic + ceil(newBasic × age%) + DR after revision (0% assumed)
arrears    = max(0, newTotal − currentTotal) × months(effectiveFrom → paymentMonth, exclusive)

pre-2016   = max( ceil(pension_31.12.2015 × 2.57) [min 9000], ceil(notionalPay_1.1.2016 × 50% | 30% normal FP) ), within limits
credit     = basic + additional + DR − commutation + FMA − other     (the finder inverts this by exact search)
DR arrears = (ceil(base × new%) − ceil(base × old%)) × months
```
Notional pay fixation itself is **not** computed (it needs each pensioner's scale history and the DoPPW concordance tables); users enter notional pay from their revised PPO.
